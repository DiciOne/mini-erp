# mini-ERP · MRP 运算内核

一个**最小但真实**的 ERP 物料需求计划（MRP）实现：从销售订单出发，展开多级 BOM，
算出每个物料该买多少、**最晚什么时候必须下单**。

**零外部依赖** —— 只用 Python 标准库（sqlite3 + datetime），clone 下来直接跑。

```bash
python demo.py            # 灌演示数据 + 跑 MRP + 打印报告
pytest test_mrp.py -v     # 7 个用例，验证算法正确性
```

## 它解决什么问题

工厂接了单，要回答三个问题：

1. 这张单要**买什么**？（BOM 展开）
2. 每样买**多少**？（净需求 = 毛需求 + 安全库存 − 现有 − 在途 − 未到货采购单）
3. **最晚什么时候下单**？（时间倒排）

只算总量的是"库存计算"；能算出"最晚下单日"的才是 MRP。

## 核心逻辑

```
销售订单（P100 × 100 台，11-10 交货）
    ↓ 展开 BOM（×2 控制板、×8 螺丝、×1 机箱）
    ↓ 递归展开子件（控制板 → ×3 芯片、×40 电阻）
    ↓ 共用件合并（控制板也用 P200，需求相加；日期取最早）
    ↓ 净需求 = 毛需求 + 安全库存 − 现有 − 在途 − 采购在途
    ↓ 最晚下单日 = 需齐日 − 提前期
采购建议（芯片 500 片，最晚 10-22 下单）
```

**时间倒排**是 MRP 的灵魂：

```
成品 11-10 交货 → 装配 3 天 → 半成品必须 11-07 到
→ 半成品的芯片采购 14 天 → 芯片必须 10-22 前下单
```

## 代码结构

| 文件 | 职责 |
|---|---|
| `db.py` | 6 张表的建表与基础读写（物料 / BOM / 库存 / 销售单 / 采购单 / 库存流水） |
| `mrp.py` | **核心**：BOM 递归展开、共用件合并、循环检测、净需求、时间倒排 |
| `seed_data.py` | 演示数据（三级 BOM + 共用件 + 各种库存形态） |
| `demo.py` | 入口：跑一遍并打印报告 |
| `test_mrp.py` | 7 个回归用例 |

## 刻意处理的三个坑

| 坑 | 不处理会怎样 | 本实现 |
|---|---|---|
| **共用件** | 一颗螺丝用在 3 个产品上，不合并 → 重复采购 3 次 | 需求相加，日期取最早 |
| **循环 BOM** | 数据录错成 A→B→A，无限递归把程序跑挂 | 递归路径检测，抛 `ValueError` |
| **供给不止库存** | 只减库存、忘了在途和未到货采购单 → 多买 | 三项都参与抵扣 |

## 已知简化

- **不做时间段分桶**：真实 MRP 会按周分桶（第 1 周缺多少、第 2 周缺多少）；
  本实现按物料归并，只保留最紧迫的需求日
- **不做产能校验**：假设车间总能做完，不考虑设备和人力上限
- **不做工作中心 / 工序排产**：那是 APS（高级排程）的范畴
